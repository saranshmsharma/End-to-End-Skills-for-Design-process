# Contributing to Design Process Prompt Library

Thanks for your interest in contributing! This library grows better with community input.

## 🎯 Ways to Contribute

### 1. Improve Existing Prompts
- Fix typos or unclear instructions
- Add better examples
- Improve formatting
- Enhance output quality based on testing

### 2. Add New Prompts
- New design process stages
- Industry-specific variations (healthcare, finance, etc.)
- Specialized use cases (mobile, accessibility, etc.)

### 3. Share Examples
- Real outputs from running prompts
- Case studies of successful applications
- Before/after comparisons

### 4. Documentation
- Improve README clarity
- Add usage guides
- Translate prompts to other languages

## 📋 How to Contribute

### Step 1: Fork the Repository
Click the "Fork" button at the top of this repository.

### Step 2: Clone Your Fork
```bash
git clone https://github.com/[your-username]/design-prompts-library.git
cd design-prompts-library
```

### Step 3: Create a Branch
```bash
git checkout -b feature/your-improvement
```

Use descriptive branch names:
- `feature/add-mobile-ux-prompt`
- `fix/research-synthesis-typo`
- `docs/improve-readme`

### Step 4: Make Your Changes
Follow these guidelines:

#### For New Prompts:
- Use existing prompts as templates
- Include "When to Use" section
- Include "Expected Output" section
- Provide clear examples
- Add bracketed `[FIELDS]` for customization
- Test the prompt yourself first

#### For Improvements:
- Be specific about what's changing
- Explain why the change is better
- Test before/after results

### Step 5: Commit Your Changes
```bash
git add .
git commit -m "Add: Mobile UX research prompt"
```

Use conventional commit messages:
- `Add:` for new prompts
- `Fix:` for bug fixes
- `Improve:` for enhancements
- `Docs:` for documentation
- `Refactor:` for restructuring

### Step 6: Push to Your Fork
```bash
git push origin feature/your-improvement
```

### Step 7: Create Pull Request
1. Go to original repository
2. Click "New Pull Request"
3. Select your fork and branch
4. Fill out the PR template
5. Submit for review

## ✅ PR Template

When creating a pull request, include:

### What does this PR do?
[Brief description of changes]

### Why is this change needed?
[Problem this solves or improvement this brings]

### How was this tested?
[How you verified the prompt works]

### Screenshots/Examples
[If applicable, show before/after or sample outputs]

### Checklist
- [ ] Followed prompt template structure
- [ ] Tested with real project
- [ ] Updated README if needed
- [ ] No typos or formatting issues
- [ ] Added to relevant index files

## 🎨 Style Guidelines

### Prompt Structure
All prompts should follow this pattern:
1. Title with emoji
2. Brief description
3. "When to Use" section
4. "What You'll Need" section
5. "Expected Output" section
6. The prompt (in code block)
7. "Pro Tips" section
8. "Next Steps" section

### Bracketed Fields
- Use `[ALL CAPS]` for placeholders
- Be specific about what should fill them
- Provide examples in description

### Examples
- Show realistic scenarios
- Use diverse contexts
- Include common mistakes to avoid

## 🚫 What Not to Contribute

Please don't submit:
- Prompts for unethical purposes
- Prompts that harm users
- Copy-paste from other sources without permission
- Spam or self-promotion
- Untested or unverified prompts

## 🤝 Code of Conduct

- Be respectful and inclusive
- Welcome newcomers
- Provide constructive feedback
- Focus on improving the library
- Credit others appropriately
